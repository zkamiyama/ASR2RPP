# ASR2RPP

**音声・動画を文字起こしし、編集できるREAPERプロジェクトを作るデスクトップアプリです。**

認識したテキストと時刻を、音声を参照するアイテムとして `.rpp` に保存します。
背景音除去・強制アライメント・話者ごとのトラック分けも選べます。元ファイルは変更しません。

## 使い始める

1. [配布ページ](https://github.com/zkamiyama/ASR2RPP/releases)から、使用するOS用の**一式ZIP**を取得します。開発中の版は[PR #7](https://github.com/zkamiyama/ASR2RPP/pull/7)に記載した成功済みCIのArtifactsから取得します。**このガイドは0.2.2以降向けです。古いCUDA入り0.2.0とは構成が異なります。**
2. 新しいフォルダーへ全展開します。Windowsは `ASR2RPP.exe`、Macは `ASR2RPP.app` を起動します。EXEだけを移動しないでください。
3. 音声・動画をキューへドラッグし、音声認識モデルを選んで **GO**。最初は **Whisper Base**、言語は音声に合わせ、追加の工程はOFF、**設定 → 時刻付与 → 自動**で試してください。
4. 選択したモデルだけが初回ダウンロードされます。完了後、入力と同じ場所にできた `.rpp` をREAPERで開きます。保存先はメイン画面で変更できます。

画面右下の歯車が設定です。表示言語は地球ボタン、または `Ctrl+Shift+L` で切り替えます。
完了したキュー行をダブルクリックすると出力フォルダーが開きます。

## 必要なもの・同梱するもの

| 対象 | 対応環境 | GPUの実行経路 |
|---|---|---|
| Windows版 | x64、AVX2対応CPU | Vulkanのみ。対応するGPUドライバーが必要 |
| macOS版 | Apple Silicon、macOS 14以降。Intel Mac非対応 | Metalのみ |

どちらもCPUで実行できます。GPUが利用できない、またはモデルとの組み合わせで失敗する場合は、該当工程の実行環境を **CPU** に変更してください。ReazonSpeech K2は同梱ワーカーではCPU専用です。

**同梱**：アプリ用Python、Qt/PySide6、NumPy、safetensors、whisper.cpp、audio.cpp、CPU版sherpa-onnxワーカー、モデルのTOML定義。
**別途必要**：プロジェクトを開くREAPER、メディア読み込み用FFmpeg、選択するモデルの重み。
**不要**：Pythonの手動インストール、PyTorch、CUDA Toolkit、Vulkan SDK、Xcode。これらの開発用ツールは通常利用には必要ありません。CUDA・CTranslate2・faster-whisperは標準配布に含めません。

FFmpegはWindowsでは未検出時にチェックサム検証付きで別途取得します。Macでは別途インストールし、検出されなければ **設定 → 詳細 → ffmpeg** に実行ファイルを指定してください。Homebrewの標準配置も検索します。
モデルとFFmpegの取得時は通信します。必要なファイルを取得した後の認識はローカルで行い、音声をクラウドの認識サービスへ送信しません。

Windows版は未署名、Mac版はad-hoc署名済み・未公証です。配布元とチェックサムを確認してください。
各ライブラリとモデルの利用条件はアプリ本体のMITライセンスとは別です。[第三者コンポーネント](THIRD_PARTY.md)を参照してください。

## モデルと時刻を選ぶ

**モデルの重みはZIPに入っていません。20種類の定義を同梱しても、全部の重みが自動ダウンロードされるわけではありません。**
WhisperのTiny〜Large/Turbo、Anime Whisper、Qwen3-ASR、SenseVoice、Fun-ASR-Nano、Nemotron、Canary、Moonshine、Voxtral、VibeVoiceなどを選べます。
対応言語・取得サイズ・実機確認範囲は[モデル一覧](docs/models.md)にまとめています。CanaryとMoonshineの同梱モデルは日本語用途には選ばないでください。

時刻の付け方は **設定 → 時刻付与**で選びます。モデルTOMLを編集する必要はありません。

| 方法 | 動作 |
|---|---|
| 自動 | 選んだモデルの時刻があれば使い、時刻のないASRはVAD発話区間を使います。アライメント工程をONにした場合は整列します。旧TOMLの既定方針も互換のため考慮します。 |
| モデルの時刻 | モデルが返す区間を使います。時刻を返さないモデルには選べません。 |
| VAD発話区間 | 声のある区間ごとに認識します。**発話区間の時刻であり、単語の境界ではありません。** |
| 強制アライメント | 認識後のテキストを音声へ整列します。メイン画面でアライメントモデルを選びます。長い発話には「アライメント前にVAD分割する」を使います。 |

文字起こし・時刻・話者は誤る場合があります。アライメントは誤認識した文章を正しく書き直す機能ではありません。
VADの最大区間長、しきい値、最小無音長も同じ設定画面で調整できます。

背景音除去は任意です。話者ダイアライゼーションも任意で、VibeVoiceのようなASR自身の話者情報も利用できます。
話者ラベルの付与と、重なった声を別の音源へ分離することは異なります。このアプリの話者工程は後者を行いません。

## 出力・停止・エラー

`.rpp` の先頭に、参照音声全体を置いたミュート済み **ORIGINAL** トラック、その下に認識アイテムのトラックを作ります。
音声はプロジェクトに埋め込みません。参照元のメディアも保管してください。
背景音除去で **RPP音声 → 処理済み**を選ぶと、連続した `*_vocals.wav` を保存し、それを参照します。原音を選んだ場合は元メディアを参照します。
同名出力は上書きせず連番にします。隣の `.asr2rpp` フォルダーは設定・時刻の出所・ログ・認識本文などの診断記録です。**外部に共有する前に個人情報を確認してください。**

停止は **STOP** を押して終了処理を待ちます。再び **GO** を押すと待機・停止・失敗した項目を処理し、完了済みの項目は残します。
完了した入力をやり直すには、キューから削除して追加し直します。エラーは画面下のログで確認できます。
「未対応のfamily」は実行環境にモデル実装がないこと、「未導入」は重みの取得が必要なことを示します。

## 保存先・更新・カスタマイズ

モデル保存先と一時領域は **設定 → 一般**で変更できます。標準のデータ領域はWindowsが `%LOCALAPPDATA%\ASR2RPP`、Macが `~/Library/Application Support/ASR2RPP` です。
アプリの更新は新しい場所へ展開します。画面設定はOSの設定領域に保存し、同じ定義の検証済みモデルは通常再利用します。取得先・revisionが変わると再取得する場合があります。

独自モデルは **設定 → 詳細 → 独自TOMLを開く**から、組み込みと重複しない名前の `.toml` を追加します。
Macの署名済み `.app` 内部は編集しないでください。TOMLは再読込、またはGO前に読み直されます。
**TOMLだけで追加できるのは、導入済みの実行環境が対応するモデル構造です。GGUFやONNXという拡張子だけで、未知のモデルまで動くわけではありません。**
